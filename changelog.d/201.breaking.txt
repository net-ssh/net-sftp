Raise `Net::SFTP::SessionClosedError` when the server closes the SFTP channel: pending requests, `download!`/`upload!` and the event loop now fail instead of hanging, sending afterwards no longer raises `NoMethodError`, and `connect!`/`Net::SFTP.start` raise if the channel closes before the version handshake. Code that relied on the previous silent return now gets an exception. Reported by @kapso (#94) and @rngtng (#115) [#201, #94, #115]
